# Каналы и комьюнити

## Единая логика площадок

У каждой площадки своя роль. Важно не дублировать всё везде подряд, а держать один бренд и разные функции.

### GitHub

**Роль:** код, релизы, репозитории, issues, contributions.

Короткое описание:

> Исходники, релизы и инженерный контур SkiF4er.

### GitBook

**Роль:** документация, архитектура, onboarding, правила бренда.

Короткое описание:

> Документация и архитектурный слой экосистемы SkiF4er.

### Telegram-канал

**Роль:** сигналы, релизы, короткие инженерные записи.

Рекомендуемое описание:

> Релизы, архитектурные заметки, open-source сигналы и спокойные анонсы экосистемы SkiF4er.

Закреплённое сообщение:

> Здесь публикуются релизы, продуктовые обновления, архитектурные заметки и короткие сигналы по экосистеме SkiF4er. Без лишнего шума — только полезный контекст.

### Telegram-чат

**Роль:** быстрое обсуждение, вопросы, связь с подписчиками.

Рекомендуемое описание:

> Обсуждение релизов, архитектуры, open-source инструментов и экосистемы SkiF4er.

### Discord

**Роль:** постоянное инженерное сообщество и место для контрибьюторов.

Рекомендуемое описание сервера:

> Комьюнити для контрибьюторов, разработчиков и тех, кто выбирает структуру вместо шума.

Рекомендуемые категории:

- **Signal** — `announcements`, `release-log`, `roadmap`
- **Build** — `frontend`, `backend`, `architecture`, `tooling`
- **Community** — `introductions`, `showcase`, `offtopic`

## Стиль модерации

- спокойно
- по делу
- без токсичности
- без флуда ради флуда
- с уважением к сильной технической дискуссии
